# The Gnani cook-call agent

A Gnani Agent Builder voice agent phones the cook each morning (and, optionally, in the evening). **CookSmart
decides what it knows; Gnani does the talking; CookSmart applies only what the cook confirmed.**

```
CookSmart ── trigger_call(variables) ──► Gnani agent ──► phone call ──► cook
    ▲   ▲                                   │  ▲
    │   └── live action  /gnani/action/{household}/cook-problem   (switch the dish mid-call)
    │       dynamic msg  /gnani/dynamic/{household}/brief          (always-fresh brief text)
    └────── post-call webhook /gnani/webhook/call-ended ◄──────────┘   (confirmed reports → stock)
```

## What the agent knows, and where it lives

| Layer | Holds | Why there |
|---|---|---|
| **Call variables** (every call) | menu, quantities, **what to use first and why**, what's on the way / missing, **allergies and house rules**, taste tips, health note, who's eating today, house style, owner's note | These change daily. A Gnani knowledge base is uploaded documents, so it can't hold them. Built by `cookbrief.py`. |
| **Prompt** (`prompt.j2`) | persona, flow, safety rules, what it must never discuss, how to confirm | Behaviour. Allergies are here **on every call**, never left to retrieval. |
| **Knowledge base** (`kb/*.md`) | the family (instructions only), allergy detail and hidden sources, taste and customs, ingredient care and **how to use ageing food**, taste guide, health notes, kitchen and emergencies, boundaries and phrasebook, units | Stable "why/how" the cook can ask about. Generated by `python -m cooksmart.gnani_cli kb`. |
| **FAQs** (`kb/faqs.json`, ≤100) | exact answers: "can Aarav have peanuts?", gas smell, spoilage | Safety questions must get one fixed answer. |

Not in the knowledge base on purpose: recipes (she knows them), prices, orders, payments, vendors, delivery
times, any diagnosis (the cook sees *"less salt, less sugar"*, never the condition), and other households' data.

## Editing it

Everything below can be edited in the app's **Agent Studio** tab (prompt, knowledge base, FAQs, household) with version history
and pre-save checks. **Download all** gives a zip to upload by hand; **Push to Gnani** updates the prompt on your agent directly.
The commands below do the same from a terminal, and `gnani_cli kb` includes any edits made in the Studio.

## Setup

1. **Keys.** Platform key with `agents` and `conversations` permissions → `INYA_PLATFORM_KEY`. (The Speech API key,
   `GNANI_API_KEY`, is a different key.) Put both in `.env`.
2. **Profile.** In the owner chat or the simulator: `Aarav is allergic to peanuts`, `spice mild`, `less oil`, or
   *Load the demo family*. Set `call the cook` and save her number.
3. **Knowledge base.** `python -m cooksmart.gnani_cli kb --household <id>` → upload `gnani/kb/*.md` in the Gnani
   console (Agent → Knowledge base) and enter `faqs.json` as FAQs. *(The Platform API in Gnani's docs has no KB upload
   endpoint, so this step is manual.)* Re-run and re-upload when the profile changes.
4. **Config.** Read Gnani's config endpoints (languages, regions, `llm_models`, `transcriber_config`, `tts_config`)
   and fill the `TODO` values in `agent_config.json` (needs `hi-IN` on both ASR and TTS).
5. **Check the prompt.** `python -m cooksmart.gnani_cli check` renders `prompt.j2` locally with strict variables and,
   if a key is set, calls Gnani's *Validate Prompt*.
6. **Deploy.** `python -m cooksmart.gnani_cli deploy` → copy the printed `botId` into `INYA_BOT_ID`.
7. **In the Gnani console:**
   * **Post-call extraction** (`post_call_extraction_v2`): the fields in `agent_config.json` → `postCallExtraction`.
   * **Dispositions:** `BRIEFED, PROBLEM_REPORTED, ON_LEAVE, RECONCILED` (plus the defaults).
   * **Post-call webhook:** `https://<your public host>/gnani/webhook/call-ended?token=<GNANI_WEBHOOK_TOKEN>`
   * **On-call action** `cook_problem` (custom HTTP, POST, arguments `problem`, `item`):
     `https://<host>/gnani/action/<household>/cook-problem?token=<GNANI_WEBHOOK_TOKEN>`
   * **Dynamic message** (optional, 10 s timeout): `https://<host>/gnani/dynamic/<household>/brief?token=…`
   * **Whitelist** the cook's number (development only calls whitelisted numbers) and import a Twilio number if needed.
8. **Test.** `python -m cooksmart.gnani_cli call --phone +91…` or run the morning step in the simulator, then read the
   conversation log and audio in the console. Iterate on the prompt (keep it in git: Gnani has no versioning).
9. **Go live.** Ask Gnani to promote to Staging, then Production.

The webhook needs a public HTTPS address (a deployed server, or a tunnel while testing). `GNANI_WEBHOOK_TOKEN` must
be set or those endpoints answer 503; a wrong token answers 401.

## Variables sent on every call

`call_type`, `cook_name`, `people`, `dishes_hi`, `start_dishes_hi`, `wait_dishes_hi`, `ingredients_hi`,
`use_first_hi`, `coming_hi`, `missing_hi`, `cautions_hi`, `taste_tips_hi`, `health_note_hi`, `people_notes_hi`,
`style_hi`, `owner_note_hi`, `reconcile_items_hi`. Values are stripped of template syntax and capped at 700 characters.

## Rules enforced in code, not in the prompt

* Only items the cook **confirmed on the call** change stock; unconfirmed ones are shown to the owner and left alone.
* The webhook is **idempotent** on the call; a live dish switch and the later webhook never switch twice.
* A **safety issue** is the last, loudest message to the owner.
* If a call can't be placed or isn't answered, the cook gets the brief as a **voice note** instead.
* Allergies are a hard filter in the planner and a hard block on any dish the owner requests.

## Verify before relying on it

These come from Gnani's documentation as summarised for this project, which itself says to confirm them:
request-body field names for create/update/trigger (a 400 names the wrong field), the exact shape the `cook_problem`
action posts, whether the webhook echoes `clientReferenceId` (we fall back to `conversation_id`), the extraction
field format, the exact config-endpoint paths.
